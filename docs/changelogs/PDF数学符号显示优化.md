# PDF数学符号显示优化说明

## 问题描述

用户反馈PDF生成中存在两个显示问题：
1. **根号符号显示不完全**：之前显示为 `√(2)` 带括号，不够美观
2. **分数显示不规范**：显示为 `(a)/(b)` 形式，而不是标准分数线形式

同时，PDF中出现`<`和`>`符号时，会被reportlab误认为HTML标签导致解析错误。

## 解决方案

### 1. 根号显示优化

**优化前**：
- `\sqrt{2}` → `√(2)` （带括号，不美观）
- `\sqrt{x}` → `√(x)`

**优化后**：
- `\sqrt{2}` → `√2` （简洁美观）
- `\sqrt{x}` → `√x`
- `\sqrt{a+b}` → `√(a+b)` （复杂表达式才加括号）

**实现逻辑**：
```python
def convert_sqrt(match):
    content = match.group(1).strip()
    content = content.replace('{', '').replace('}', '')
    
    # 单个数字或字母：不加括号
    if re.match(r'^[a-zA-Z0-9]+$', content):
        return f"√{content}"
    
    # 包含运算符：加括号便于阅读
    elif any(op in content for op in ['+', '-', '*', '/', ' ']):
        return f"√({content})"
    
    # 默认不加括号
    else:
        return f"√{content}"
```

### 2. 分数显示优化

**优化前**：
- `\frac{1}{2}` → `(1)/(2)` （不美观）
- `\frac{a}{b}` → `(a)/(b)`

**优化后**：
- `\frac{1}{2}` → `½` （使用Unicode分数字符）
- `\frac{1}{3}` → `⅓`
- `\frac{3}{4}` → `¾`
- `\frac{a}{b}` → `a/b` （复杂分数用斜杠，去掉多余括号）

**支持的Unicode分数字符**：
```
½ ⅓ ⅔ ¼ ¾ ⅕ ⅖ ⅗ ⅘ ⅙ ⅚ ⅛ ⅜ ⅝ ⅞
```

**实现逻辑**：
```python
fraction_unicode = {
    '1/2': '½', '1/3': '⅓', '2/3': '⅔', '1/4': '¼', '3/4': '¾',
    '1/5': '⅕', '2/5': '⅖', '3/5': '⅗', '4/5': '⅘',
    '1/6': '⅙', '5/6': '⅚', '1/8': '⅛', '3/8': '⅜', '5/8': '⅝', '7/8': '⅞'
}

def convert_fraction(match):
    numerator = match.group(1).strip()
    denominator = match.group(2).strip()
    frac_key = f"{numerator}/{denominator}"
    
    # 优先使用Unicode分数字符
    if frac_key in fraction_unicode:
        return fraction_unicode[frac_key]
    else:
        # 复杂分数使用斜杠，去掉多余括号
        return f"{numerator}/{denominator}"
```

### 3. HTML特殊字符转义修复

**问题**：
- 文本中的 `b<a` 或 `a²<c²` 被误认为HTML标签
- reportlab解析器报错：`invalid attribute name 矛盾；若`

**解决方案**：
```python
# 1. 先转义所有HTML特殊字符
text = text.replace('&', '&amp;')
text = text.replace('<', '&lt;')
text = text.replace('>', '&gt;')

# 2. 再恢复我们故意添加的粗体标签
text = text.replace('&lt;b&gt;', '<b>')
text = text.replace('&lt;/b&gt;', '</b>')
```

这样确保数学不等式符号 `<` 和 `>` 不会被误解析为HTML标签。

## 注意事项

1. **Unicode分数限制**：
   - 只有常见的分数（如½, ⅓, ¾）有Unicode字符
   - 其他分数（如5/7）仍使用斜杠形式
   - 这是Unicode标准的限制，无法避免

2. **根号复杂度判断**：
   - 单个字符或数字：不加括号（如 √2, √x）
   - 包含运算符：加括号（如 √(a+b)）
   - 这样既保证了简单情况的美观，又保证了复杂情况的清晰

3. **网页vs PDF**：
   - 网页使用MathJax渲染LaTeX，效果最佳
   - PDF使用Unicode字符近似显示，效果次之
   - 两者无法完全一致，但已经尽可能接近

## 后续可优化方向

如果未来需要更完美的PDF数学公式显示，可以考虑：

1. **使用reportlab的flowables**：
   - 创建自定义的分数Flowable，绘制真正的分数线
   - 但实现复杂度较高

2. **使用matplotlib渲染公式**：
   - 将LaTeX公式转换为图片
   - 嵌入PDF中
   - 但会增加文件大小

3. **使用专业的LaTeX to PDF工具**：
   - 如pandoc + XeLaTeX
   - 但需要额外依赖和复杂配置

当前的Unicode方案是在**效果、性能、复杂度**之间的最佳平衡点。
